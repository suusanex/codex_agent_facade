# 外部エージェントの統括

親の判断力を要所に使い、調査・実装の重複と不要なコンテキスト読み込みを減らす。Astra専用のモデル設定は行わず、現在の親モデルで実施する。

## 適用と責任

- ユーザーが指定した期間・対象に適用する。「このスレッド」と指定された場合は、変更指示までその方針と委譲先を引き継ぐ。指定がなければ今回のタスクに適用する。
- 親は目的・制約・受入条件の理解、重要な設計判断、作業分解、成果の統合判断、レビュー、受入、ユーザーへの説明を担当する。
- 外部workerは広範な調査、コード・ドキュメント等の成果物作成と編集、テスト実行、修正、必要な統合作業を担当する。親は修正が小さくても成果物を直接編集して代替しない。親の会話上の計画・判断・指示・回答作成は許可する。
- 「調査のみ」「プランまで」等の依頼範囲をworkerにも守らせる。このSKILLの使用を実装開始の許可と解釈しない。
- 親は判断・レビューに必要な資料、コード、差分、検証結果を直接確認してよい。委譲済みの探索やテストを同じ範囲で最初から繰り返さず、根拠不足や具体的な懸念を解消する確認に絞る。

## 委譲先と接続

ユーザー指定のagentを使う。未指定なら既に合意した選択を用い、それもなければ委譲先だけを確認する。無断で別agentや組み込みサブエージェントへ切り替えない。

`codex_agent_facade`のMCP toolを直接利用する。既存の`github-copilot`等の中継用SKILLは、親の分割・レビューを禁止する別契約なので、この統括のためには呼び出さない。workerへ渡すのは実作業に必要なSKILLだけとし、この親用SKILLや親の委譲方針をそのまま渡して再委譲させない。

具体的な引数・待機・再試行・session継続は、実際に公開されているMCP toolの説明に従う。未公開のモデル指定や使用量取得等を仮定しない。接続できない場合、設定変更や直接CLI起動で代替せず、阻害要因を報告する。

## 作業の渡し方

まず目的と受入条件、重要な未確定事項を把握する。詳細な現状把握が必要なら、それ自体をworkerへ委譲し、根拠付き報告から設計を判断する。親が全コードを読み終えてから委譲する必要はない。

作業は、一つの結果をレビューできるまとまりで渡す。ファイルやコマンドごとの細切れ委譲を避ける。並列化は独立性と編集範囲が明確な場合に限り、同一ファイルや同一sessionを競合して操作させない。必要なworkspace分離もworkerへ依頼し、既存変更を保護させる。

workerへの指示には、必要な範囲で次を含める。会話全文や既に読めるファイル本文を機械的に複製しない。

- 作業目的、今回の担当範囲と対象外、許可された操作（調査のみ／編集可等）。
- 決定済みの制約・設計、入力の参照先、編集対象workspace、他作業との境界。
- 受入条件と必要な検証。ユーザー判断や親の設計判断へ戻すべき未確定事項。
- 報告内容：結論、変更箇所または調査根拠、実施した検証と結果、未解決事項。詳細はファイル・差分・ログの参照先を示し、全文再掲は必要時に限る。

workerが親の会話履歴・認証・ファイルへのアクセスを共有すると仮定しない。アクセスできない入力は必要部分だけ受け渡す。親のみに適用する役割指示と、workerが守るプロジェクト制約を区別する。

## 結果の受入と修正

jobの完了はタスクの達成を意味しない。短い報告から確認を始め、受入条件に照らして実際の差分・成果物・検証根拠の重要部分を確認する。workerの自己申告だけで合格にしない。未検証の点は未検証として扱う。

修正可能な不足は、根拠・期待結果・修正範囲を添えてworkerへ戻す。同じ作業の修正は対応する外部sessionを継続し、独立した作業のsessionとは混ぜない。親が把握した重要な判断変更はworkerにも伝える。改善が続く限り必要な修正を進め、根拠なく固定回数で打ち切らない。

外部agentを利用できない、または成果物が目的から大きく逸脱し、レビューと修正依頼では解決の見込みがない場合は、影響する作業を止める。無断の親実装や別agentへの切替は行わない。阻害要因、完了済みの成果、残作業、再開に必要な選択を報告する。同じ失敗を新しい証拠や条件変更なしに反復しない。

通信失敗とworker失敗を区別し、実行中のjobを二重起動しない。待機timeoutだけで失敗と判断しない。停止・取消の扱いはMCP契約に従い、実行中jobを放置したまま終了したように報告しない。

## 継続と最終報告

長い作業では、方針と委譲先、受入条件、作業ごとのworkspace・job・sessionの対応、状態、次の判断を簡潔に引き継ぐ。引継ぎファイルが必要ならworkerへ作成を依頼する。

最終回答は親が統合し、達成内容、検証根拠、残る制約を説明する。workerの発言をそのまま合格報告として転送しない。実測していないトークン削減や費用削減を断定しない。
